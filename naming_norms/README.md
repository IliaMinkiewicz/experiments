# Апробация называний — макет

Сбор норм называния для 82 новых стимулов + 12 якорей из существующей базы.
Показывается только серая (однозначная) версия. Задача участника — написать название
и оценить лёгкость называния по шкале 1–7.

**Состояние: не опубликовано.** В `config.js` стоит `enabled: false`, страница
показывает «набор закрыт». Данные не отправляются.

## Архитектура

Задание и данные лежат в **двух разных репозиториях**:

| Что | Где | Видимость |
|---|---|---|
| задание (эта папка) | `IliaMinkiewicz/experiments`, ветка `main`, каталог `naming_norms/` | публичный |
| данные участников | `IliaMinkiewicz/naming-norms-data`, каталог `data/` | **приватный** |

Разделение обязательно, и по двум причинам сразу.

Приватность. Репозиторий с заданием обязан быть публичным — этого требует GitHub Pages.
В файлах ответов есть возраст, пол, ответ про родной язык, идентификатор исполнителя
с площадки и сведения о браузере. Лежи они в том же репозитории, их читал бы кто угодно
по прямой ссылке.

Сборки Pages. Каждый коммит в ветку, из которой собирается сайт, запускает пересборку,
лимит — около 10 сборок в час. При 195 участниках это тысячи коммитов, и страница задания
начала бы отдавать ошибку в разгар набора. Чужой репозиторий через Pages не собирается,
поэтому вопрос снимается сам и ветка нужна обычная — `main`.

## Развёртывание

**1. Приватный репозиторий для данных.** Один раз:

```bash
gh repo create naming-norms-data --private
git init -b main && mkdir -p data && touch data/.gitkeep
git add -A && git commit -m "репозиторий для данных апробации"
git remote add origin https://github.com/IliaMinkiewicz/naming-norms-data.git
git push -u origin main
```

Публичным его делать нельзя никогда — см. выше.

**2. Токен.** Settings → Developer settings → Personal access tokens → Fine-grained.
Доступ только к `naming-norms-data`, права **Contents: Read and write**, срок 90 дней.
К `experiments` доступ не нужен: задание туда кладётся руками.
Нигде не коммитить — токен живёт только внутри Apps Script.

**3. Apps Script.** Новый проект на script.google.com, вставить `google_apps_script.js`,
заполнить блок НАСТРОЙКИ (репозиторий и ветка уже проставлены). Развернуть как
веб-приложение: запуск от своего имени, доступ «у всех». Запустить `selfTest()` —
в `naming-norms-data` должен появиться `data/_selftest.json`.
**Проверить, что в `experiments` ничего не появилось.** Удалить тестовый файл.

**4. Задание.** Содержимое этой папки положить в `main` в каталог `naming_norms/`.
Pages на репозитории уже включён (там работает RMET), отдельно настраивать не нужно.

**5. `config.js`:** вписать `uploadUrl` (URL из шага 3) и `secret` (то же значение, что в Apps Script).

**6. Проверить перед запуском** — см. чек-лист ниже. Затем `enabled: true`.

## Ссылка

Одна на всех, номер списка в ней не указывается:

```
https://iliaminkiewicz.github.io/experiments/naming_norms/?w=ИДЕНТИФИКАТОР_ИСПОЛНИТЕЛЯ
```

`w` — идентификатор исполнителя, подставляемый площадкой. Если подстановка не настроена,
параметр можно опустить: участнику присвоится случайный `anon_*`, а связь с выплатой
пойдёт через код завершения.

`?list=1|2|3` открывает конкретный список в обход распределения — только для тестирования.

## Как назначается список

На старте страница спрашивает у Apps Script (`action=counts`), сколько участников
**завершило** каждый список, и берёт наименее наполненный; при равенстве — жребий,
иначе несколько человек, стартовавших одновременно, дружно уйдут в один и тот же список.
Выбор запоминается в `localStorage` по идентификатору исполнителя, поэтому перезагрузка
страницы не перебросит человека на другой список и картинки не повторятся.
Если `counts` не ответил, список выбирается жребием — участника не теряем.

Считаются только файлы с суффиксом `__final`: брошенные на середине прогоны список
не закрывают. Побочный эффект — на волне одновременных стартов счётчики отстают,
и распределение слегка перекашивает. На горизонте всего набора это выравнивается.

## Яндекс Задания

1. **Один проект, один пул, одно задание.** Интерфейс у всех трёх списков одинаков,
   различается только номер, а его выдаёт само приложение. Три проекта означали бы
   тройное дублирование инструкции при каждой её правке.
2. Тип: задание с внешней ссылкой и полем ввода кода завершения.
3. **Запрет пересечения получается сам собой:** задание выдаётся исполнителю один раз,
   второй раз он его не увидит. Механика навыков не нужна.
4. Перекрытие (сколько исполнителей выполняет задание) — 195 = 65 × 3.
5. Фильтры: регион РФ, **возраст 18–45**, русский язык, десктоп. Возрастная рамка
   совпадает с текстом согласия и с проверкой в форме демографии — расхождение между
   ними было бы противоречием в собственных документах. Фильтр на десктоп обязателен:
   с телефона задание отдаёт экран «нужен компьютер», и исполнитель уйдёт впустую.
6. Приёмка **не автоматическая**: код из формы сверяется с полем `code` в данных.
7. Цена — по медианному времени с пилота, не заранее.
8. **Пилот 10 человек** до основного набора.

Целевой набор: 65 человек на список (ожидаемые ~50 после отбраковки).
Якоря наберут около 150 ответов, новые стимулы — около 50.

## Формат данных

Одна порция = один файл `data/L{список}/{pid}__{код}__{время}.json`
в приватном репозитории `naming-norms-data`.
Внутри `rows` — по записи на карточку:

`code, pid, worker, list, seed, version, kind, pos, stim_id, file, check,
answer, latin, ease, rt_first_key, rt_submit, ts`

`kind`: `main` — обычная карточка, `check` — прямая проверка внимания.
`check: "attention"` — стимул-якорь со старым согласием 100 %.
`latin` — ответ набран латиницей (не исправляется автоматически, решается на анализе).
Файл с `__final` содержит ещё и `meta`: демография, время, разрешение экрана, user-agent.

## Известные ограничения

**Кнопки «не знаю» нет** — по решению исследователя. Незнакомый объект участник
всё равно как-то назовёт, поэтому «не узнал» в данных неотличим от «узнал неверно».
Частичный индикатор — оценка лёгкости 6–7.

**Точная формулировка шкалы** из опроса 2022 года не сохранилась; используется
реконструкция «Насколько легко было подобрать название? 1 — очень легко, 7 — очень сложно»
с тем же направлением (1 = легко). При сравнении с якорями это надо оговаривать.

**`secret` виден в исходнике страницы.** Он отсекает случайный мусор, но не защищает
от намеренной подделки. Ограничения на стороне Apps Script: длина запроса и флаг `ACCEPTING`.
